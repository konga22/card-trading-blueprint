# Catalog Taxonomy

## 목적

이 문서는 카드 탐색과 검색에 필요한 분류 체계를 정리한다. 목표는 입문 사용자가 너무 많은 필터에 눌리지 않으면서도, 숙련 사용자는 상세 조건으로 빠르게 범위를 좁힐 수 있게 하는 것이다.

## 사용자 노출 분류

### 1차 게임 분류

- `all`
- `pokemon`
- `yugioh`
- `onepiece`
- `other`

### 2차 목적 분류

- `beginner`
- `collection`
- `play`
- `rare`

### 3차 포맷 분류

- `single`
- `graded`
- `set`
- `box`

## 상세 필터

상세 필터는 기본 홈 화면에 전부 노출하지 않는다. `search`와 `search/advanced`에서 단계적으로 사용한다.

- `set`
- `cardNumber`
- `language`
- `rarity`
- `edition`
- `holoType`
- `condition`
- `gradingCompany`
- `gradeScore`
- `priceRange`
- `sellerCondition`

## 검색 모델

### 기본 검색 입력

기본 검색은 아래 필드를 우선 대상으로 한다.

- 카드명
- 세트명
- 카드번호

### 상세 탐색 확장

상세 탐색에서는 아래 조건을 추가한다.

- 언어
- 희소도
- 에디션
- 홀로 타입
- 상태
- 그레이딩 회사
- 점수

## 라우트별 분류 밀도

### 홈 `/`

- 행동 선택과 대표 탐색만 보여준다.
- 게임 분류와 대표 검색 진입만 허용한다.
- 상세 필터를 직접 노출하지 않는다.

### 탐색 `/discover`

- 게임, 목적, 발견형 섹션을 중심으로 보여준다.
- 카드 비교보다 “무엇을 볼지 정하는 단계”에 가깝다.

### 검색 `/search`

- 자유 검색과 기본 칩, 추천 검색어를 제공한다.
- URL 상태를 통해 현재 검색 문맥을 공유할 수 있어야 한다.

### 상세 검색 `/search/advanced`

- 세트, 번호, 언어, 상태 등 상세 필터의 진입점이다.
- 입문 화면에서 감추었던 세부 조건을 여기서 다룬다.

## URL 상태 제안

검색 상태는 가능하면 아래 키를 사용한다.

- `q`
- `game`
- `purpose`
- `format`
- `condition`
- `sort`

상세 필터가 늘어나더라도 의미가 드러나는 키를 유지한다.

## 네이밍 규칙

- 내부 키는 영문 소문자와 언더스코어를 사용한다.
- 사용자 라벨은 짧고 명확하게 유지한다.
- 게임명, 포맷, 상태명은 문서와 코드에서 같은 키를 재사용한다.
